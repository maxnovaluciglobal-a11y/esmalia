## Reglas obligatorias

1. **RLS en toda tabla nueva.** Usar helpers `is_clinic_member(clinic_id)`, `has_clinic_role(clinic_id, roles[])`, `can_manage_clinic(clinic_id)`. Ver `supabase/migrations/20260726*.sql` para la definición.
2. **`clinical_notes*` SOLO owner/admin/dentist/assistant.** `payments` excluye assistant. No revertir estas policies sin auditoría (ver `oralia_audit_fase6.md`).
3. **Nunca `git push --force` a main** — push a `main` es deploy a producción y reescribir su historia rompe los worktrees y PRs abiertos. (La razón vieja, el sync de Lovable, ya no aplica desde el desacople del 31-ago-2026.)
4. **`types.ts` de Supabase se parchea a MANO** cuando agregás tabla/enum nuevo. Bloque `Row/Insert/Update/Relationships` + añadir al `Enums`. ⚠️ **Esto es evitable y conviene arreglarlo**: el CLI de Supabase ya es devDependency (`supabase` en `package.json`) y existe el script `npm run types:gen` — solo falta `supabase login` (o `SUPABASE_ACCESS_TOKEN`) para poder regenerar y hacer `git diff` en vez de auditar el drift a mano. Auditado el 04-sep: hoy NO hay drift (55/55 tablas, 669/669 columnas, 19/19 enums, 6/6 RPCs), pero los `Relationships` de 8 tablas nuevas quedaron vacíos y eso rompe cualquier embedded `select('t(col)')` futuro.
5. **Migraciones tienen dos pasos:** (a) archivo en `supabase/migrations/` versionado, (b) aplicar al Supabase propio via `psql "postgresql://postgres.hvfkygoguxvpmwslrccb@aws-0-sa-east-1.pooler.supabase.com:5432/postgres" -f <archivo>` con `PGPASSWORD` del `.env`. Sin este segundo paso el schema queda desfasado. (El Lovable MCP `query_database` apunta al proyecto huérfano de Lovable Cloud: legado, solo para un rollback, no recomendado).
6. **Dinero:** `bigint` cents. `formatMoney(cents, currency)` respeta ISO zero-decimal (CLP/PYG/COP/JPY/etc). Nunca dividir por 100 asumiendo. `currency` es **obligatorio** en `formatMoney`/`toCents`/`fromCents`: sin default, el compilador encuentra los sitios que no tienen la moneda a mano. Todo input de dinero va con `MoneyInput`, que habla cents y muestra la unidad visible con el `step` correcto.
7. **Fechas y timezones:** `hoyISO(timezone)` con `access.clinic?.timezone`, nunca sin argumento. `wallTimeInTzToUtc` en `appointments.functions.ts` es la referencia para interpretar `<input datetime-local>` en tz de la sucursal.
8. **Correlativos** (presupuestos, futuros): vía RPC atómica `next_clinic_counter(clinic_id, kind, year)`. Nunca `count(*)+1`.
9. **Nunca UPDATE de eventos versionados** (odontogram_marks, clinical_note_versions). Patrón: INSERT nueva fila + trigger SECURITY DEFINER cierra la anterior.
10. **Snapshots inmutables** cuando algo depende de catálogo: copiar `name_snapshot` + FK `ON DELETE SET NULL`. Renombrar catálogo no muta el histórico.
11. **Placeholders nullable en vez de fabricar cero:** `saldo`, `no_show_risk`, `ai_summary`. UI muestra "Sin datos" cuando null, no 0.
12. **Nunca `||` para caer a un default cuando 0 es un valor legítimo** — usar `??`. Ya causó un bug real: `patient_cents` de 0 (convenio que cubre el 100 %) caía al precio de lista y le cobraba al paciente lo que el seguro ya había pagado. Ver `fetchPatientBalances`.
13. **Nada de caracteres invisibles en el fuente.** Los rangos de diacríticos van escapados (`\u0300-\u036f`), nunca con los caracteres literales. `scripts/check-invisibles.mjs` corre en lint-staged y lo rechaza — se agregó después de que pasara tres veces el mismo día (un byte NUL y dos regex).
14. **La moneda nunca viaja desde el cliente.** Ninguna server function acepta `currency` en su schema: el trigger `moneda_desde_la_clinica` (BEFORE INSERT en `expenses`, `lab_orders`, `payments`, `procedures`, `quotes`, `treatment_plans`) la fija desde `clinics.currency` y las columnas ya no tienen `DEFAULT 'CLP'` — si el trigger falta, el INSERT revienta contra el NOT NULL en vez de escribir Chile en silencio. Es la misma lección que `created_by`: un DEFAULT solo aplica si el cliente omite la columna, un trigger que sobreescribe siempre hace imposible el error.
15. **Todo gate de permiso de la UI necesita su par en el servidor.** El JWT vive en `localStorage`, así que cualquier miembro puede llamar un server fn directo. Para dinero, el helper es `requireFinanceView` (`finance-reports.functions.ts`). RLS sola no alcanza: `treatment_items_select_members` y `payments_select_members` dejan leer a roles sin `finance:view`.
